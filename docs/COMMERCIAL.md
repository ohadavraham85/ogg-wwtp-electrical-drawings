# OhadCad — הכנה למסחור

מסמך עבודה: מה כבר מוכן, מה חוסם השקה מסחרית, ומה ההחלטות שלך. מסודר לפי סדר ביצוע מומלץ.

## מה כבר הוכן (נובמבר 2026)
- **רישיון קנייני** (`LICENSE`): "כל הזכויות שמורות". עד עכשיו לא היה רישיון בכלל.
- **הודעות צד שלישי** (`THIRD_PARTY_NOTICES.md`): Firebase, pdf.js, jsPDF, הגופנים, וסימנים מסחריים של יצרנים.
- **חלון "אודות OhadCad"** בתפריט: גרסה, זכויות יוצרים, רכיבי צד שלישי, סימנים מסחריים, והבהרת אחריות מקצועית.
- **טיוטות משפטיות** (`legal/`): תנאי שימוש, מדיניות פרטיות, הצהרת נגישות. **לא מקושרות עדיין** — קודם להשלים את השדות המסומנים ולקבל אישור עורך דין, ואז להוסיף אותן ל-`LEGAL` ב-`cad.html`.
- **לוגו הלקוח בטבלת השרטוט**: לוגו מבט"י מוצג כברירת מחדל רק לבעלים. משתמש אחר מתחיל בלי לוגו ומעלה את שלו.

## שלב 1 — חוסמים (חובה לפני גבייה)
1. **ריבוי ארגונים (Multi-tenant).** היום יש "תיקייה משותפת" אחת: כל משתמש מאושר רואה את כל הפרויקטים. במוצר מסחרי כל לקוח (ארגון) צריך מרחב נפרד משלו, עם מנהל ומשתמשים. זה שינוי במבנה הנתונים ב-Firestore, בכללי האבטחה, ובמסך הכניסה/אישור.
2. **הרשמה עצמית במקום אישור ידני.** היום כל משתמש חדש ממתין שהבעלים יאשר אותו. במוצר: הרשמה → ניסיון חינם → מינוי בתשלום.
3. **סליקה ומינויים.** צריך ספק תשלומים ושרת קטן שמקבל את אישורי התשלום (Webhook) ומעדכן את סטטוס המינוי, שכללי האבטחה בודקים.
   - אפשרויות: ספק ישראלי (Grow/משולם, Cardcom, Tranzila, PayPlus) — מתאים ללקוחות בישראל, עם חשבונית בעברית. או Paddle / Lemon Squeezy, שהם "מוכר רשמי" ומטפלים במע"מ בעולם. יש לבדוק מול הספקים מה זמין לעסק ישראלי.
   - דורש מעבר של פרויקט Firebase לתוכנית **Blaze** (תשלום לפי שימוש), בשביל Cloud Functions.
4. **הקוד חשוף.** המאגר ב-GitHub ציבורי, וכל אחד יכול להעתיק את האפליקציה. להעביר למאגר פרטי ולארח ב-**Firebase Hosting** (או Cloudflare Pages) עם דומיין משלך. GitHub Pages ממאגר פרטי דורש מנוי GitHub בתשלום.
5. **תיקיית `archive/`** (האפליקציה הישנה של המט"ש) מפורסמת באתר הציבורי. להוציא אותה מהאתר המסחרי.

## שלב 2 — משפטי ועסקי
- רישום עסק (עוסק מורשה / חברה בע"מ), חשבון בנק עסקי, והפקת חשבוניות אוטומטית (למשל חשבונית ירוקה / iCount, שמתחברים לספקי הסליקה).
- **עורך דין**: אישור תנאי השימוש ומדיניות הפרטיות, כולל עמידה בחוק הגנת הפרטיות ובתיקון 13 שלו.
- **נגישות**: שירות שפונה לציבור בישראל מחויב בהצהרת נגישות ובהתאמות. מומלץ בודק נגישות מוסמך, ואז לעדכן את ההצהרה.
- **שם וסימן מסחרי**: לבדוק ש-"OhadCad" פנוי לרישום כסימן מסחר, ולרשום דומיין (ohadcad.co.il / .com).
- **אחריות מקצועית**: התנאים כבר מבהירים שהשרטוט הוא כלי עזר. כדאי לשקול ביטוח אחריות מקצועית.

## שלב 3 — מוצר
- **דף נחיתה ותמחור**: מה המוצר, צילומי מסך, מסלולים, כפתור "התחל ניסיון".
- **תמחור**: הצעה ראשונית — מסלול יחיד (לפי משתמש לחודש), מסלול צוות (ארגון עם כמה משתמשים), והנחה שנתית. להחליט לפי קהל היעד: חשמלאים עצמאיים, משרדי תכנון, רשויות ותאגידי מים.
- **הכוונה למשתמש חדש**: תבנית לדוגמה נפתחת, וסיור קצר בכפתורים.
- **תמיכה**: כתובת מייל עסקית, ומרכז עזרה עם שאלות נפוצות וסרטונים קצרים.
- **מגבלות לפי מסלול**: למשל מספר פרויקטים, ייצוא DXF, תמונות רקע — אם רוצים מסלול חינמי.

## שלב 4 — תפעול ואמינות
- **פרויקט Firebase נפרד לייצור**, עם App Check (הגנה מפני שימוש לרעה), התראות תקציב וגיבוי יומי אוטומטי של Firestore.
- **תמונות רקע**: היום הן נשמרות בתוך הפרויקט (גבול 1MB לכל פרויקט ב-Firestore). להעביר ל-Firebase Storage כדי לאפשר תמונות ופרויקטים גדולים.
- **ניטור תקלות** (Sentry או דומה) וסטטיסטיקת שימוש בסיסית, בהסכמת המשתמש.
- **ניהול גרסאות**: סביבת בדיקות לפני עדכון ללקוחות, והודעת "מה חדש" (קיימת).
- **ייצוא נתונים ומחיקת חשבון** בלחיצה. זה גם דרישת פרטיות.
